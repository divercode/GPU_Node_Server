## 1. 软件概述

星轨算力是面向两台自用 GPU 服务器的轻量监控与作业管理平台。平台不提供费用、账单或计价功能，只做资源监控、作业管理、告警、用量统计和平台自运维。

主要模块：

- 工作台：GPU 总览、利用率趋势、节点热力图、最近作业、告警动态；
- 资源目录：GPU 分区、型号、资源池、快速提交；
- 作业中心：作业筛选、详情、日志、GPU 指标；
- 集群总览/GPU 监控：节点、GPU 卡级状态、温度、功耗、显存、XID；
- 告警中心：分级、确认、时间线、规则命中；
- 资源用量：课题组 GPU·h、30 天趋势（仅资源量，无金额）；
- 管理：用户与账户、告警规则、审计日志、系统状态。

## 2. 运行环境

### 2.1 服务端

- 2 台 GPU 服务器，x86_64；
- Rocky Linux 9.6 或 Ubuntu 24.04 LTS；
- Docker Engine 24+、Docker Compose v2；
- 内网固定 IP，开放 8080/TCP；
- NVIDIA 驱动 570 系列，DCGM 4.5+（真实采集时）。

### 2.2 客户端

- Chrome / Edge / Firefox 最近两个主版本；
- 建议 1440×900 以上分辨率，支持平板/手机响应式。

### 2.3 启动

在项目根目录：

```bash
docker compose up -d --build
docker compose ps
```

浏览器访问：`http://<内网IP>:8080/`。

## 3. 登录与角色

### 3.1 登录

- 容器模式：进入 Dex 登录页，输入邮箱和密码；
- 本地开发模式：输入不带 `@` 的用户名和密码。

首次为某个客户端登录时，Dex 可能显示一次“Grant Access”，确认后进入平台。

### 3.2 角色

| 角色 | 主要权限 |
|---|---|
| 平台管理员 | 全部页面、系统配置、用户/审计、全局监控 |
| 运维人员 | 监控、GPU、告警、规则、系统、用户只读 |
| PI | 工作台、资源目录、本人作业、本组用量 |
| 普通用户 | 工作台、资源目录、本人作业、本组用量 |
| 审计只读 | 用量、审计、监控只读 |

普通用户看不到 GPU 监控、告警中心、用户管理、系统状态等入口；直接输入受限路由也会回到工作台。

## 4. 工作台

管理员工作台展示：

- GPU 总量、已分配卡数、运行/排队作业、严重告警、本月 GPU·h；
- GPU 利用率趋势（24h）；
- GPU 状态分布环图；
- 节点负载热力图；
- 分区排队压力；
- Top 课题组用量；
- 最近作业和告警动态。

普通用户工作台只展示本人作业、账号、本组资源用量，不显示全局节点/GPU 数据。

## 5. 资源目录与作业

### 5.1 资源目录

- 查看分区、GPU 型号、可用卡数、占用率和排队 P95；
- “申请资源”进入快速提交表单；
- 快速提交只预估 GPU·h 和排队时间，不计算费用。

### 5.2 作业中心

- 按状态、分区、关键字筛选；
- 运行中作业显示进度和已运行时长；
- 点击作业查看详情：资源、生命周期、日志、GPU 指标；
- 普通用户只能看到本人作业，管理员/运维可查看全部。

## 6. 集群总览与 GPU 监控

- 节点表显示在线/降级/Drain、GPU 使用数、利用率、平均温度；
- GPU 卡页显示每张卡的状态、利用率、显存、温度、功耗、UUID；
- 点击 GPU 卡打开抽屉：最近 1 小时负载、资产信息、关联作业、健康检查；
- 按分区视图可按节点/分区聚合；
- 页面每 15s 轮询刷新，存在抽屉/弹窗/输入操作时暂停自动刷新，避免打断。

## 7. 告警中心

- 按严重/警告/信息分级；
- 支持列表与时间线视图；
- 每条告警显示节点、GPU、规则、时间、状态；
- 运维/管理员可确认、静默；
- 告警来源为 DCGM/Prometheus/平台组件（真实环境）或示例数据（原型环境）。

## 8. 资源用量

- 仅统计 GPU·h，不显示费用/金额；
- 管理员可看全局、本组、本人；普通用户仅本组/本人；
- 支持 30 天堆叠趋势和课题组占比；
- 数据来源为 slurmdbd 作业记录（真实环境）。

## 9. 用户、审计与系统状态

- 用户页：账号、角色、课题组、GPU·h 使用、状态、最近登录；
- 审计页：操作人、动作、对象、时间、来源 IP、哈希链状态；
- 系统状态：slurmctld/slurmdbd/OOD/Dex/FreeIPA/Prometheus/DCGM 等组件健康、延迟、证书。

## 10. 安全与权限说明

- 平台不保存用户 LDAP 密码；容器模式由 Dex/FreeIPA 完成认证；
- 前端不保存 OIDC token；
- 后端只信任带共享密钥的网关注入身份头；对象级权限在后端校验；
- 写接口使用 CSRF double-submit：`portal_csrf` cookie + `X-CSRF-Token`；
- 建议生产使用 HTTPS 443，并设置安全 cookie；
- 普通用户无法通过直接输入 URL 越权访问管理页面；
- 演示账号和静态密码上线前必须更换。

## 11. 常见问题

| 问题 | 处理 |
|---|---|
| 8080 打不开 | 检查容器状态、端口映射、内网防火墙 |
| 登录后循环跳转 | 检查 `PUBLIC_BASE_URL` 是否与浏览器地址完全一致 |
| API 返回 401 | 检查网关/后端共享密钥、OIDC session |
| 页面没有实时数据 | 检查 agent 是否上报、API 是否在线、浏览器网络 |
| 普通用户看不到工单/告警 | 属于 RBAC 预期行为，需运维/管理员角色 |
| 页面数据不刷新 | 确认页面在前台、没有打开抽屉/弹窗/输入框聚焦 |

## 13. API 与权限

### 13.1 统一响应

```json
{
  "code": "OK",
  "message": "ok",
  "data": {},
  "request_id": "..."
}
```

错误码：`AUTH_REQUIRED`、`FORBIDDEN`、`OBJECT_SCOPE_DENIED`、`NOT_FOUND`、`VALIDATION_FAILED`、`RATE_LIMITED`、`INTERNAL_ERROR`。

### 13.2 主要接口

| 接口 | 说明 | 权限 |
|---|---|---|
| `/api/v1/health` | 健康检查 | 公开/网关 |
| `/api/v1/me` | 当前用户、角色、账号、CSRF token | 已登录 |
| `/api/v1/catalog` | 资源目录 | 已登录 |
| `/api/v1/nodes` | 节点状态 | admin/ops/auditor |
| `/api/v1/gpus` | GPU 指标 | admin/ops/auditor |
| `/api/v1/jobs` | 作业列表（普通用户仅本人） | 已登录 |
| `/api/v1/alerts` | 告警列表 | admin/ops/auditor |
| `/api/v1/usage` | GPU·h 用量 | 按角色/范围 |
| `/api/v1/users` | 用户目录 | admin/ops |
| `/api/v1/audit` | 审计事件 | admin/ops/auditor |
| `/api/v1/system/status` | 组件健康 | admin/ops |
| `/api/v1/collector/ingest` | agent 上报 | 采集 token |

### 13.3 数据范围规则

- 普通用户：仅本人作业、本组用量；
- PI：本组作业/用量；
- 运维/管理员：全局作业、GPU、节点、告警、系统；
- 审计只读：全局只读用量/审计/监控；
- 前端只负责展示，后端必须逐对象校验。

## 14. 部署与运维

### 14.1 首次部署

1. 安装 Docker Engine 和 Compose v2；
2. 复制 `.env.example` 为 `.env`；
3. 设置 `PUBLIC_BASE_URL=http://<内网IP>:8080`；
4. 执行 `docker compose up -d --build`；
5. 检查 `docker compose ps` 和 `curl http://<IP>:8080/healthz`；
6. 浏览器登录 Dex。

### 14.2 日常检查

- 网关健康：`/healthz`；
- 后端健康：`/api/health`、`/healthz`；
- 容器日志：`docker compose logs -f gateway backend dex oauth2-proxy`；
- 磁盘/备份/证书：系统状态页；
- GPU agent：检查 `source=agent` 与 `updated_at`。

### 14.3 升级和回滚

- 升级前备份 `.env`、Dex 配置、证书；
- 保留最近 5 个镜像版本；
- 先升级 Dex/oauth2-proxy，再升级 gateway/backend；
- 回滚时恢复镜像 tag 和配置；
- 升级后复验登录、API、GPU agent、告警。

## 15. GPU 服务器 agent

```bash
python agent.py --server gpu-01 --backend http://<平台IP>:8080 --token <PORTAL_COLLECTOR_TOKEN>
```

- agent 只读取 GPU 指标，不执行作业；
- 建议 systemd 托管；
- 默认 15s 上报；
- 无法连接时本地重试，不影响 GPU 作业。

## 17. 常见问题（补充）

- **登录循环**：`PUBLIC_BASE_URL` 与浏览器地址不一致；修改后重启 compose。
- **Dex 回调失败**：检查 Dex client redirect URI 是否与 `.env` 一致。
- **API 401**：检查网关共享密钥、OIDC 会话、`/api/v1/me`。
- **agent 401**：token 不一致；检查 `.env` 的 `PORTAL_COLLECTOR_TOKEN`。
- **页面空白**：打开浏览器控制台，检查 `/api/v1/health`、`/api/v1/me` 是否 200。
- **权限不足**：确认 Dex/LDAP 组是否正确，后端按组映射角色。
- **端口冲突**：`PORTAL_HTTP_PORT` 与宿主机 8080 占用冲突时修改映射。

## 18. 附录：数据字典

### 18.1 作业状态

`running` 运行中、`pending` 排队中、`completed` 已完成、`failed` 失败、`cancelled` 已取消。

### 18.2 GPU 状态

`allocated` 使用中、`idle` 空闲、`error` 故障、`drain` 隔离。

### 18.3 告警状态

`firing` 未恢复、`acked` 已确认、`resolved` 已恢复。

### 18.4 时间与单位

- 时间：毫秒时间戳/ISO 8601；
- 资源量：GPU·h；
- 温度：℃；
- 功耗：W；
- 显存：MB/%。
