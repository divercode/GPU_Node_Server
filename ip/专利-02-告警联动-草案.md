# 发明专利申请草案

## 一种GPU集群告警—作业—节点联动处置方法及系统

> 草案说明：本文件是技术交底书/权利要求草案，不是正式申请文件；申请前必须做专利检索，并由专利代理师根据真实实现和实验数据改写。文中“示例”不构成对现有技术的承认或对效果的保证。

## 一、技术领域

本发明涉及 GPU 集群监控告警与作业调度技术领域，尤其涉及一种 GPU 集群告警—作业—节点联动处置方法及系统。

## 二、背景技术

GPU 集群通常使用 DCGM exporter、Prometheus、Alertmanager 采集和产生告警。现有告警平台可以按规则通知值班人员，但告警与 Slurm 作业、GPU、节点、账号之间往往彼此割裂：

1. 同一故障会触发多条告警（XID、温度、节点状态、作业失败），值班人员需要手工合并；
2. 告警只知道节点/GPU，不知道影响了哪些作业和用户；
3. 处置动作（确认、静默、drain、取消作业、建工单）分散在多个系统，缺少统一策略和审计；
4. 自动处置没有幂等、限速和审批边界，可能误操作或重复操作；
5. 处置后缺少恢复指标验证，告警可能长期悬挂或过早关闭。

## 三、发明内容

### 3.1 要解决的技术问题

本发明要解决的技术问题是：如何将分散的告警、GPU、作业、节点和账号信息构建为可关联的事件图，自动完成去重、根因归并、影响面计算、分级处置和恢复验证，从而减少无效告警和人工操作。

### 3.2 技术方案

一种 GPU 集群告警—作业—节点联动处置方法，包括：

**S1、告警标准化接入。**  
从监控系统接收告警，提取并标准化以下标签：集群、节点、GPU 标识、规则名、严重级别、发生时间、作业 ID、用户/账号；对缺少 GPU/作业标签的告警，保留节点/规则级信息。

**S2、构建事件图。**  
以告警、GPU、节点、作业、账号为节点，以“发生于”“运行于”“分配到”“属于”“关联”为边构建事件图；按时间窗口和拓扑邻接关系将告警合并为事件簇。

**S3、去重与根因归并。**  
在同一事件簇内，按规则优先级和拓扑因果关系确定根因告警：例如同一 GPU 的 XID 致命错误优先于由其引起的温度/利用率异常；节点 down 优先于其上的作业失败；对重复告警和派生告警进行抑制，只保留根因和影响面。

**S4、影响面计算。**  
沿事件图查询根因关联的 GPU、节点、运行中作业、排队作业、用户和账号，计算影响面指标：受影响作业数、GPU 数、节点数、用户数、是否影响共享队列；按规则生成影响面评分和通知范围。

**S5、分级处置策略。**  
根据根因类型、严重级别、影响面、映射置信度和白名单，选择处置动作：

- 自动确认/静默重复告警；
- 通知用户/值班/负责人；
- 创建工单并附影响面；
- 对白名单内的致命故障执行节点 drain 或 GPU 禁排；
- 对需要人工审批的动作生成待办，不直接执行；
- 对单位时间内的自动动作限速，并保证幂等。

**S6、执行与审计。**  
执行处置动作，记录操作人/策略、告警、对象、前后值、request_id 和结果；对需要二次确认的动作记录审批人。

**S7、恢复验证与关闭。**  
在处置后按恢复窗口检查相关指标：XID/ECC 计数、温度、功耗、GPU 利用率、节点状态、作业状态；满足恢复条件后自动关闭事件并解除静默；不满足则升级告警或转人工。

### 3.3 有益效果

- 将 XID、温度、节点状态、作业失败等多条告警归并为一个事件，减少噪声；
- 自动计算受影响作业/用户/节点，缩短故障通知和处置时间；
- 通过策略引擎统一确认、通知、drain、工单、审批和审计；
- 通过幂等、限速、审批边界降低自动处置风险；
- 通过恢复验证避免告警长期悬挂或过早关闭。

## 五、具体实施方式

### 5.1 示例环境

2 台 GPU 服务器、16 张 A100、Slurm 调度、DCGM exporter + Prometheus + Alertmanager；平台后端通过 API 接收告警并维护 GPU/作业/节点缓存。

### 5.2 事件合并示例

同一时刻产生：

- `gpu_xid_fatal`：`gpu-02` GPU 0，XID 79；
- `gpu_temp_high`：`gpu-02` GPU 0，温度 86℃；
- `node_down`：`gpu-02`；
- `job_failed`：作业 `200103`，退出码 1。

S2 以 `gpu-02` 和作业 `200103` 为关联节点，将 4 条告警合并为一个事件簇；S3 依据“GPU 致命 XID > 节点 down > 温度 > 作业失败”的优先级确定根因为 XID 79，其余作为派生告警抑制。

### 5.3 影响面示例

S4 查询到根因 GPU 映射到作业 `200103`（2 卡），该作业属于“智能计算组”，节点 `gpu-02` 上有 3 个运行作业、2 个排队作业；影响面为作业 4 个、用户 3 个、账号 1 个、节点 1 个。

### 5.4 处置示例

策略引擎判断 XID 79 属于白名单致命故障，自动执行节点 drain 并创建工单；对作业 `200103` 通知负责人；对同节点其他作业仅通知、不自动取消。所有动作带幂等键，10 分钟内同一事件不重复 drain。

### 5.5 人工审批示例

若根因是“温度持续偏高”但未达到致命阈值，策略只生成待办，由运维选择“确认/静默/降权/迁移”；选择迁移时再调用调度器接口，审批人写入审计。

### 5.6 恢复验证示例

更换故障卡后，连续 6 个采集周期 XID/ECC 为 0、温度低于阈值、节点状态为 idle，S7 关闭事件并解除静默；若 30 分钟内仍不满足，升级为严重事件并通知值班。

## 七、摘要

本发明公开一种 GPU 集群告警—作业—节点联动处置方法及系统。该方法将告警、GPU、节点、作业和账号构建为事件图，按时间窗口和拓扑关系合并事件簇，依据规则优先级和因果关系确定根因并抑制派生告警；沿事件图计算受影响作业、节点和用户，生成影响面评分；策略引擎根据根因、严重级别、影响面和白名单执行确认、通知、工单、节点 drain、GPU 禁排或人工审批，并通过幂等、限速、审计和恢复验证形成闭环。该方法可降低告警噪声和人工处置成本，提高故障通知与恢复的准确性。
